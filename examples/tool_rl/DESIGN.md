# tool_rl 实验设计说明

> 在 verl 上复现 Qwen3 工具调用 RL（GRPO）。核心思路：**规则化奖励判对错、数据反复制造"选择/弃权"情境、训练侧让学不会的题反复学**。以下每项都按"问题 → 解决措施 → 措施背后的逻辑"展开。

---

## 一、奖励设计 —— 规则式三维打分

**背景问题**：工具调用 RL 很难给分——模型输出是结构化调用，普通文本答案奖励无法判断"调用是否正确、参数是否合理"。LLM-judge 又不稳定、不可复现、成本高。

**措施与逻辑**：放弃 RM/judge，只用**可解释的规则奖励**，把"工具调用好不好"拆成三个互不混淆的维度加权求和（默认 `0.60×Dim1 + 0.20×Dim2 + 0.20×Dim3`，权重可用 env 覆盖，**允许负分**以压制乱猜）。

| 维度 | 权重 | 打分方式 | 学什么 |
|------|------|----------|--------|
| Dim1 工具正确性 | 0.60 | 对标签做**与顺序无关的一对一匹配**——`name=匹配数/并集(Jaccard)`、`param=参数值匹配/并集`；未声明调用每个 `-0.1`；全部未匹配则按调用数 `-0.1×n` | 用哪个工具、传什么值 |
| Dim2 格式合规 | 0.20 | `thinking→<tool_call>` 布局检查：严格门（think 闭合/唯一/随后有内容）+ 调用前有非空 think | 先思考再调用，别"想完就停" |
| Dim3 调用格式 | 0.20 | 输出调用与标签**只比对工具名、参数名、参数类型**（忽略值） | 调用本身的写法对不对 |

**一个关键工程细节（Dim1）**：
- **问题**：如果"未声明工具"的惩罚对 0 做 floor，那么"调了未声明工具"(被截为 0) 会反超"声明了但多余调用"(-0.1)。
- **措施**：惩罚**始终叠加在匹配分上，不做 floor**。
- **逻辑**：把"乱调"压得比"误调"更低，保住正确排序。

**弃权行为塑造**（`TOOL_RL_ABSTAIN_MODE=keyword`，可选）：
- **问题**：当标签表明"无需工具"时，模型易发生"乱调用 / 瞎猜"。
- **措施**：用规则分类器（非 reward model）重塑 Dim1/Dim3——澄清/声明无工具得满分，乱猜 0.4，乱调 0.2，未声明乱调更低。
- **逻辑**：让规则奖励显式偏袒"不会就承认/询问"，而非编造答案或硬调工具。

## 二、数据生成 —— 五层精心设计（`prepare_data.py`）

### 2.1 数据集混合与去污染
- **问题**：单个基准会让模型过拟合某一种工具/写法，且训练数据若含评测同源样本会虚高。
- **措施**：混 **APIGen / ToolACE / Hammer / API-Bank / Seal-Tools** 五个基准；**刻意排除 BFCL**（其样本与评测基准重叠）。
- **逻辑**：多源提升泛化，排除重叠源保证评测可信。

### 2.2 任务塑形成"工具选择"问题
- **问题**：API-Bank / Seal-Tools 原始格式只点名"正确 API"，模型背记即可，学不到"从一堆工具里选中对的"。
- **措施**：给这类样本**注入 5 个语义相近的干扰工具**；并在每条首条 user 消息统一注入 `<instruction>`，鼓励多轮澄清、别一步到位、别臆测信息。
- **逻辑**：干扰工具把任务从"命中记忆"重新塑造成"选择 + 排除"；instruction 则引导模型走"逐步澄清—决策—调用"的稳健路径。

### 2.3 数据增强（默认 15% 正样本）
- **问题**：模型可能过拟合到具体工具名/描述/参数名，遇到改名或错误描述就崩。
- **措施**：对用到标签工具的样本做扰动，每个样本从打乱顺序的策略中取第一个可用：
  - **tool_rename**：换工具名（标签跟随）→ 抗"工具命名漂移"。
  - **desc_replace**：换不相关描述 → **变成负样本**（标签清成 `[]`，非 `None`，区分"无需工具"与"无标签"）。
  - **param_rename**：重命名参数名（标签 arguments key 跟随）→ 抗参数名漂移。
  - **default_shuffle**：随机改参数默认值 → 抗"背默认值"。
- **逻辑**：把工具当作"可实例化的本体"而非死记的字符串；同时用 desc_replace 原地"制造"负样本供下一层调整弃权分布。
- **注意**：任何突变都必须**同步 `task["tools"]` 与 `metadata["tools"]` 两份 schema 拷贝**，否则奖励/彩排读到的是不一致的 schema。

### 2.4 负样本塑造（学会"该弃权就弃权"）
- **问题**：reward 偏袒弃权，但各数据集的负样本占比失控，模型要么罕见"无需工具"场景，要么过度弃权。
- **措施**：
  - **strip_tool_declarations**：清掉一部分原始负样本的工具声明，造出"prompt 根本没给工具"的类型（正确行为是说无工具/请求信息）。
  - **trim_negatives**：把负样本占比拉到目标（默认 25%）——过多随机丢弃，**不足则用 `desc_replace` 把正样本降级成负样本补足**（`--no-neg-topup` 可关）。
- **逻辑**：用"工具列表被清空"和"描述不匹配"两种方式制造弃权情境，保证训练集里"该弃权"的比例稳定到目标值，reward 的弃权偏好才有足够样本可用。

### 2.5 防泄漏切分
- **问题**：ToolACE/API-Bank 同一会话的多个 turn 上下文高度重复，若按"样本"随机切分，同一会话会同时跨进训练与验证，造成近重复泄漏、验证分虚高。
- **措施**：按**会话组**（去掉 `-t1`/`-c3` 等 turn 后缀的 key）切 train/val，同一会话的所有 turn 整组落在一个集合。
- **逻辑**：保证验证集与训练集在"会话级"不重叠，测的是真实泛化而非对见过的上下文做记忆。

## 三、训练侧机制

### 3.1 提示注入（hint_injection）
- **问题**：部分工具查询很难稳定 rollout 成功，而一条固定 hint 会让策略过度依赖特定措辞。
- **措施**：维护一个**同义改写池**，全部传达同一组语义（保持谦逊不臆造信息 / 工具间有调用顺序依赖 / 调用前先推理）；不同样本随机取不同变体；混入 25% 的"无 hint"对照组；`extra_info["hint_id"]` 记录选用了哪个变体，便于按变体离线分析。
- **逻辑**：用"多种措辞 + 无 hint 混入"防止策略死记某一句话，同时保证学到的是语义而非字面；每 epoch 重新采样避免固定的"样本-变体"配对被过拟合。

### 3.2 难题回放（hard_replay）
- **问题**：全零 reward 的"难题"组被 DAPO 过滤后梯度为 0，之前学不会的题就永远学不到，能力原地踏步。
- **措施**：在 DAPO `filter_groups` 之外，把全零组在后续 step 中**重新生成**供模型再学，并**按成功率分层**调度：
  - ≤1% 的难题 → 每约 20 step 回放一次（hard 层）。
  - 1%~50% → 提升到 medium 层，每约 10 step 回放一次。
  - ≥50% → 视为已掌握，**移出**回放池。
  - 回放样本占每步上限 20%，避免挤占新样本。
- **逻辑**：带宽留给真正"学不会"的样本，掌握得越差回放越频繁，练会后逐级毕业，形成"针对性加练"而非均匀重跑。

### 3.3 结合 DAPO 分组过滤
- **措施**：开启 `filter_groups`（`metric=score`），只保留 reward 有区分度（std≠0）的组参与更新。
- **逻辑**：与难题回放互补——过滤去掉"均匀 reward"的噪音组，回放则确保被过滤掉却仍有价值的难题不丢失学习信号。

## 四、整体设计意图（一句话）

**奖励**把"对错"拆分并允许弃权，**数据**反复制造"选择 vs 弃权"的情境并防泄漏，**训练**用提示注入保格式、用分层回放把学不会的题逐步练会、用 DAPO 过滤去噪音。

三者的闭环：**数据教模型"见过什么"，奖励告诉它"什么算对"，回放保证"之前学不会的最后学会"。**
